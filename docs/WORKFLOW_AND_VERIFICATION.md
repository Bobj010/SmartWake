# Регламент разработки и 3-слойной верификации SmartWake

> **Назначение**: Адаптация методологии Vibecoder School (`vibecoding-methodology` и `task-verification`) под специфику мобильной разработки на Native Android (Kotlin + Jetpack Compose).  
> **Главный закон**: Фраза «Всё готово» не принимается без объективных доказательств (зеленые тесты, эмуляция негативных сценариев, проверка системных разрешений и сборка APK).

## 2. Три слоя верификации (3-Layer Verification для Android)

```
[Слой 1: JUnit 5 / MockK] ──► [Слой 2: Compose UI & Robolectric] ──► [Слой 3: Security & OS Policy]
  • Доменная логика               • Рендеринг Compose-экранов          • Разрешения в Manifest
  • Генератор математики          • Интеракции (кнопки, ввод)          • Изоляция WakeLock
  • Валидация Barcode Hash        • Ошибочные состояния UI             • Офлайн-приватность
```

### Слой 1: Модульные автотесты (Unit / Logic Layer)
* **Инструменты**: JUnit 4/5, MockK, Kotlinx Coroutines Test, Turbine (для тестирования StateFlow).
* **Что тестируется строго ДО написания кода (TDD)**:
  1. `MathGeneratorTest`: генерация примеров уровней Easy, Medium, Hard (отсутствие деления на 0, корректность ответов).
  2. `DateTimeUtilsTest`: корректный расчет времени до следующего звонка с учетом дней недели и перехода через полночь (например: сейчас 23:45, будильник на 00:15).
  3. `BarcodeValidatorTest`: корректность сверки хешей и защита от пустых строк.
  4. `AlarmStateFlowTest`: корректный переход состояний `Ringing` -> `MissionActive` -> `Dismissed`.

### Слой 2: Проверка пользовательского интерфейса (Compose UI Test / Robolectric)
* **Инструменты**: `compose-ui-test-junit4`, Robolectric.
* **Что тестируется**:
  1. Отображение всех элементов карточки будильника (время, переключатель, название).
  2. Невозможность нажать кнопку выключения до ввода правильного ответа математики.
  3. Корректность работы экранного цифрового блока калькулятора (ввод цифр, очистка `Backspace`, кнопка `Enter`).
  4. Адаптивность под размеры экранов смартфонов (Safe Area, отступы под системную жестовую панель).

### Слой 3: Системная безопасность и аудит политик Android
* **Что проверяется**:
  1. Все фоновые службы объявляют `foregroundServiceType` согласно требованиям Android 14.
  2. Обязательный релиз `WakeLock.release()` в блоке `finally {}`, исключающий утечку батареи.
  3. Проверка того, что изображения с камеры никогда не сохраняются на диск и не передаются в сторонние логи/сети.

## 3. Матрица негативных тест-кейсов (Specific Negative Matrix)

| Вектор отказа | Негативный сценарий | Ожидаемая реакция системы |
| :--- | :--- | :--- |
| **1. Пустые/битые данные** | Создание будильника без выбора дней недели при разовом аларме. | Автоматическая установка на ближайшее наступление этого времени (сегодня или завтра). |
| **2. Неверный QR-код** | Пользователь сканирует штрих-код пачки чая вместо зубной пасты. | Звук ошибки, короткая вибрация, сообщение «Код не совпадает!», будильник продолжает звонить. |
| **3. Перезагрузка системы** | Телефон сел или перезагрузился ночью. | `BootReceiver` перехватывает `BOOT_COMPLETED`, читает активные будильники из Room и заново ставит их в `AlarmManager`. |
| **4. Отказ камеры** | Пользователь закрыл объектив пальцем или в комнате полная темнота. | Кнопка «Включить фонарик» доступна в 1 клик прямо в видоискателе. |
| **5. Потеря кода (Форс-мажор)**| Код физически уничтожен/утерян. | Ввод аварийного 6-значного PIN-кода или автоотключение через 5 минут непрерывного звонка (Safe-Exit). |
| **6. Попытка читерства** | Пользователь нажимает кнопки громкости на торце смартфона, чтобы заглушить звук. | Перехват события изменения громкости и возврат звука на максимальный уровень звонка. |
